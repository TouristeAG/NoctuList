# QR du bénévole dans l'espace bénévole : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un bénévole non admin affiche son QR depuis l'espace bénévole (PWA), y compris hors ligne, à la place d'Apple Wallet.

**Architecture:** Les appareils (et le serveur à l'inscription) publient un document `volunteerPortalQr/{uid}` à côté de la page `volunteerPortal/{uid}`, lisible seulement par son propriétaire quand le réglage est actif. Le portail le lit, l'affiche en plein écran et le garde dans `localStorage`. Un service worker limité à `/v/` rend la page disponible hors ligne.

**Tech Stack:** Kotlin Multiplatform (Compose), Firestore rules, Cloud Functions TypeScript, JS vanilla ES modules, `qrcode-generator` (MIT).

**Spec:** `docs/superpowers/specs/2026-11-12-portal-qr-design.md`

## Global Constraints

- Contenu du QR : exactement `volunteer.id`, comme l'e-mail. Jamais pour un admin (`isAdmin`).
- `volunteer.id` n'apparaît jamais dans `volunteerPortal/{uid}` ni dans l'export JSON.
- Clé de réglage : `volunteer_portal_qr_enabled`, absente = activé, `"false"` = coupé. Firebase uniquement.
- Collection : `volunteerPortalQr`, document `{ schema: 1, payload, name }`.
- Règles Firestore : `NOCTULIST_RULES_VERSION = 16`. `firebase/firestore.rules` et `shared/src/commonMain/composeResources/files/firestore.rules` restent identiques.
- Le site source est `webform/` ; `shared/src/commonMain/composeResources/files/webform` est recopié par la tâche Gradle `syncWebFormResources` (ne pas l'éditer à la main). `webform/functions/lib/index.js` est régénéré par `npm --prefix webform/functions run build`.
- Textes : seulement les libellés « Afficher le QR dans l'espace bénévole », « Mon QR », « Fermer ». Aucun texte d'aide, aucun tiret cadratin. App : 7 langues (`values`, `-fr`, `-es`, `-hi`, `-la`, `-zh-rCN`, `-zh-rTW`). Portail : `en`, `fr`, `es`, `de`, `it` dans `webform/portal-i18n.js`.
- Kotlin tests : `./gradlew :shared:desktopTest --tests "com.eventmanager.app.portal.*"`. Règles : `cd firebase/tests && npm run test:rules`. Functions : `cd firebase/tests && npm run test:functions`.

## Review Focus

1. Un bénévole passe admin alors que son QR est publié : le document doit disparaître au publish suivant, et le QR gardé sur son téléphone doit être effacé au prochain chargement en ligne. (Task 1 test `qrDocRemovedWhenVolunteerBecomesAdmin`, Task 4 effacement sur `exists() == false`.)
2. Valeur du réglage écrite en chaîne (`"false"`) et non en booléen : la règle doit couper dans les deux cas. (Task 3 tests `qrBlockedWhenSettingStringFalse` et `qrBlockedWhenSettingBoolFalse`.)
3. Page retirée (accès révoqué, bénévole supprimé) : le document QR doit partir avec elle, pas rester orphelin. (Task 1 test `qrDocRemovedWithStalePage`.)
4. Deux personnes se connectent tour à tour sur le même téléphone : le QR de la première ne doit jamais s'afficher pour la seconde. (Task 4, `readCachedQr(orgId, uid)` compare l'`uid`.)
5. Premier lancement hors ligne de l'app installée : les modules Firebase de gstatic doivent être en cache, sinon la page ne démarre pas. (Task 5 vérification manuelle DevTools « Offline » après un seul chargement en ligne.)
